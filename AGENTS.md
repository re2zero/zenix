## CONVENTIONS
- **Rust 2024 edition**, GPL-3.0-or-later
- **UI depends on the component library + `gpui-pre` only** — `use gpui::*` for GPUI (`gpui = { package = "gpui-pre", version = "=0.3.10" }`), the window comes from `gpui_platform::application()`, and drawing primitives come from `ely_core`. Never add `gpui-kit` / `gpui-component` back, and keep every Ely crate on the one pinned commit (`rev = "30c66fe1d5d23db769a6c834b771d054d7f288cf"`) so entity types cross the seam untranslated
- **GPUI patterns**: Entity/Context/Action model, `cx.spawn()` for async, `FocusHandle` for focus
- **No state mutation in `render()`**, with one recorded exception: `TerminalView`'s paint path calls `Regions::views`, which creates and updates the per-pane paint entities, and GPUI exposes no prepaint-only hook for that at this pin (`src/terminal/view.rs` carries the comment; `window.use_keyed_state` is the same shape and only valid while a frame is being built)
- **Every shell surface is a module of `src/ui/`, and every command is one row of `src/ui/commands.rs`**: a chord (keymap), a palette row and the chrome's own trigger all run through `Root::run_command`, so none of the three can drift from what the command does — do not add a second table or a second dispatch path
- **One UI face, inherited from the root; one mono, named by the terminal**: `Root`'s outermost frame sets `.font_family(cx.theme().font_family)` (the component library's Inter), so markdown bodies, source feet and every other inheriting line speak the same face as the library's components; `TerminalView` names `cx.theme().mono_family` because its cells are laid on a fixed advance. Never install a font of zenix's own or name another face — text that inherits would otherwise fall back to gpui's platform default (IBM Plex Sans), the split that the U4-5 report caught
- **A plugin action is one declaration**: palette row, chord and MCP tool all come from `src/plugins/actions.rs`'s `Catalog` — never assemble one of the three from `plugin.action.list` directly
- **A disabled plugin is offered nowhere**: `plugin.action.list` still answers for one while `plugin.action.invoke` refuses it (`plugin_disabled`), so `Catalog::runnable` filters before offering; its *declarations* stay readable through `PluginState.declared`
- **No `unwrap()`/`expect()` in render or request paths** — a user-triggered path answers or degrades instead of panicking; report errors with `anyhow::Context`/`thiserror`. Recorded exceptions: startup invariants (`TOKIO_HANDLE`, thread spawns) carry a message `expect`, and mutex `lock().unwrap()` follows Rust's poisoning convention
- **Platform-gated code** in `src/platform.rs` only; core uses `#[cfg(...)]` on imports/fns
- **Client settings live in the config global**: read with `config::get`, write with `config::update` (value + behavior + file move together); settings the daemon acts on belong in its own `config.toml` — see `src/config/mod.rs`'s module docs
- **Config is JSONC** (comments allowed), walked against a schema on every load: an unknown key is dropped, a wrong type falls back per field, an out-of-range number is clamped, and each is reported as a diagnostic
- **User-visible strings resolve through `locales/zenix.yml`** (`t()` / `t!`); strings read by the *model* — tool descriptions, prompts, context-collection output — stay verbatim on purpose (see `src/ai/tools.rs`'s module docs), and config diagnostics keep their terse English (they quote JSON paths and type names; see `src/config/mod.rs`'s module docs)
- **Endpoint is the state truth**: workspace/tab/pane/agent state comes from `ClientEvent::Snapshot` pushes — do not add polling
- **No local PTY**: daemon panes are the only terminal source (the local PTY/alacritty path was removed by decision)
- **Herdr binary is pinned, not built**: `vendor/herdr-pins.tsv` records version + per-platform SHA-256; `scripts/fetch-herdr.sh` downloads that release into `res/herdr` (gitignored), `build.rs` copies it beside the client and a release build refuses a seed that does not match. The client auto-seeds `~/.local/bin/herdr` on first run; herdr self-updates thereafter, and `zenix-probe` reports when the running daemon's version differs from the pin
- **Packaged assets**: zenix ships and embeds no font of its own. The component library's assets carry Inter, JetBrains Mono and IBM Plex Sans in the binary, so nothing is read from disk; their SIL OFL-1.1 texts (`licenses/ely/*-OFL.txt`) and the library's MIT text ship under `/usr/share/doc/zenix/ely/`. There is no theme JSON: the chrome's palette comes from the component library and the config's four layers (`src/ui/theme.rs`). License texts (project GPL, the library's MIT and its fonts' OFL, herdr's Apache-2.0 from `licenses/herdr/LICENSE`, vendored crates' Apache-2.0 with NOTICEs) ship under `/usr/share/doc/zenix/`; the inventory is `THIRD-PARTY.md`

## ANTI-PATTERNS (THIS PROJECT)
- ❌ Building without a daemon seed — run `scripts/fetch-herdr.sh` once; a dev build without `res/herdr` silently falls back to whatever herdr is installed
- ❌ Editing `vendor/herdr-{protocol,client}/**` casually — they are local source now, but a change to `wire.rs` is a protocol decision: record it in `vendor/HERDR_UPSTREAM.md` and say why
- ❌ Reintroducing the herdr submodule, or a source build of the daemon — the pin (`vendor/herdr-pins.tsv`) plus `scripts/fetch-herdr.sh` is the contract
- ❌ Adding UI deps or API calls without checking the real `gpui-pre 0.3.10` / component-library signatures first (read the source at the pinned commit; the library is the authority on its own API)
- ❌ Mutating state in GPUI `render()` (the retired shell's `Regions::views` call site is history, not precedent)
- ❌ Adding a shell command anywhere but `src/ui/commands.rs`'s directory — the chord, the palette row and the chrome trigger must all read the one table
- ❌ Keeping a setting in a view struct beside the config, or writing `config.json` directly instead of through `config::update`
- ❌ Hardcoding theme colors — use theme provider tokens
