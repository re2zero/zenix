00 · OVERVIEW

先换骨，再换皮

现在树里同时有 gpui-kit 的 Theme、gpui-component 的控件和组件库的聊天组件：三套 token、两套输入行为、两套主题缓存。彻底换到组件库不是“把 import 改掉”，而是把外壳按组件的语义重新组合，并删掉旧的设计系统。

01

为什么现在换

gpui-kit 与组件库各有一套主题和控件。继续并存会让设置、输入法、焦点与快捷键继续分裂；组件库已经有 AppShell、Settings、Chat、Agent、Terminal 与一套语义 token。

02

换到什么

UI 只依赖 组件库 + gpui-pre 0.3.10（GPUI Kit 0.8.1 用的同一快照）。终端 painter 保留（它是 daemon surface 的绘制器，不是组件库），但只使用组件的 token 与 gpui-pre 类型。Cargo 里不再出现 gpui-kit / gpui-component。

03

不做什么

不引入本地 PTY，不改 daemon 协议，不做客户端无法执行的假开关。业务状态仍留在 src/ai、src/herdr、src/plugins，这次只换 UI 层。

版本说明：0.8.1 是 GPUI Kit 的版本号；组件库最新 main 是 30c66fe（核心包 0.2.0 / 其余 0.1.1），它钉的 gpui-pre 0.3.10 正是 GPUI Kit 0.8.1 用的同一快照。所以「基于 0.8.1」在这里 = 组件库 30c66fe + gpui-pre 0.3.10 + Rust 1.98.1，不把 gpui-kit 加回来。
主题不再自建：直接用组件库的主题系统——模式（深色 / 浅色 / 跟随系统）、强调色（预设 + 自定义）、代码主题（标准 / 静谧 / 纸面）、以及可选的导入/编辑。删除 Zenix 主题 JSON、五个自建 family 和终端自建调色板；品牌身份靠布局、组件库的 Inter + JetBrains Mono 字体与图标。设置页 100% 卡片式；管理面用抽屉/模态，主区域永远留给终端。

设计原则

A

终端是锚点

窗格卡片 1px 发丝线、8px 间距；chrome 退后，终端内容占最大面积。管理面不接管主区域。

B

按组件的语义用色

accent 只给主操作与选中，focus 只给焦点；danger 只给破坏性动作，warning 只给等待/需注意。不自建品牌色。

C

发丝线，不堆阴影

层级靠 surface 的明度差和 1px 边框；阴影只给真正浮起的层：palette、dialog、drawer。

D

卡片只用于分组

设置、舰队、插件合同用卡片；不为每一行、每一个窗格套卡片，避免“卡片汤”。

E

每个面写明数据源

侧栏脚注写 snapshot / event / plugin.list；只读事实标“只读”，不把不可执行的东西做成开关。

F

键盘与指针同等

每个动作都有 chord，每个 chord 都能在面板里找到；点击是最短的路径，不是唯一路径。

主题的四层配置

01

模式 ThemeSelector

Light / Dark / System 三档；只切换 Palette，不改布局与组件。系统切换可即时跟随。

02

强调色 AccentColorPicker

命名预设（由 zenix 传入）+ 任意自定义色；只覆盖强调色，不重建整块调色板。焦点仍是蓝色。

03

代码主题 SyntaxThemePicker

标准 / 静谧 / 纸面三套语法配色，各有明暗；只影响代码与 markdown 代码块，不改 UI。

04

自定义 ThemeImporter / ThemeEditor

可选的高级入口：导入一份调色板 JSON，或在组件的主题编辑器里改；不是 zenix 的默认路径。

已经定下的：主题只用组件库的系统，不再维护 Zenix / Gruvbox / Solarized / Tokyo Night / Matrix 五个自建 family 和主题 JSON。默认是深色 + 默认强调色 + 标准代码主题；强调色、代码主题和自定义导入都由组件提供。

12 · MIGRATION

新分支实施计划

已拍板；在 feat/ui-shell 上按 U0–U4 做，不做长期兼容层：每个阶段结束都能编译、能运行、能截图对比。目标是 cargo tree -i gpui-kit 为空。

U0 · 依赖手术 0.5–1 天

固定组件库 30c66fe 与 rust-toolchain.toml（1.98.1）；加入 gpui-pre 直接依赖；删掉 gpui-kit / gpui-component；先让空壳编译；更新 THIRD-PARTY（组件库 MIT）与 AGENTS。

U1 · 设计系统 1–2 天

把现有视觉映射到组件 Palette / Syntax，不维护五个 family；写 config → theme 同步（mode / accent / syntax / 自定义导入）；替换 h_flex/v_flex、Theme、Icon、Button、Input；删掉 gpui-kit 主题缓存；终端 painter 改用 gpui-pre 类型。

U2 · 壳层 2–3 天

AppShell / TitleBar / ActivityBar / TabBar / StatusBar / Sidebar / SplitPane；侧栏与对话折叠；面板拖拽；窗格卡片与聚焦态。

U3 · 管理面 3–5 天

命令面板、设置卡片页、对话（大部分已在）、舰队、插件抽屉、事件检查器、布局模态、工作树与共享确认。

U4 · 清理与验收 1–2 天

cargo tree 证明无 gpui-kit；fmt / clippy / test / probe；按本文逐面截图对比；cargo deb；AGENTS 与文档收尾。

已知风险

风险处理
gpui-pre 0.3.9 → 0.3.10组件库最新 main 已升到 gpui-pre 0.3.10（GPUI Kit 0.8.1 钉的同一快照），并要求 Rust 1.98；实验分支还是 0.3.9 + Rust 1.96。先锁 1.98.1、只升依赖、编译 vendored terminal/input，再动 UI，避免把两件事混在一起。
组件缺少 slot标签上的智能体点、窗格标题等，在 src/ui/ 组合，不 fork 组件库；缺口记录到 upstream issue。
硬编码英文工具卡“Arguments/Result”等由 zenix 包一层 i18n，或向上游提 PR；不复制组件。
主题配置accent 只覆盖 accent，syntax 只覆盖代码，终端 ANSI 跟随深色 / 浅色模式；自定义导入只接受调色板 JSON，不做组件级覆盖。没有对应 token 的（title_bar 等）别名到 surface/border，不新增私有 token。
输入法行内 preedit仍是 GPUI XIM 的上游限制；组件的 TextInput 继承它。提交可用，行内候选不承诺。
